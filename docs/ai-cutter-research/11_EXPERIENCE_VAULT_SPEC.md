## Two objects

### Historical fact

A `CorrectionEvent` from [10](./10_TIMELINE_DIFF_RESEARCH.md) after a human arrangement exists. It is immutable. It records what changed, which evidence the AI cited, and which policy ran. It does not record "user disliked silence cuts" as a sentence.

Facts can also include: the arrangement was discarded with no edit (cost unknown, not zero), and the arrangement was promoted unchanged (a zero-diff fact).

### Derived preference hypothesis

```text
PreferenceHypothesis
  id
  status: hypothesis          # never fact
  statement                   # token, e.g. margin.end.ms = 360
  scope: global | user | project_type | project | scene_type
  scopeRef                    # user id, project id, or type tag
  supportIds[]                # correction event ids
  counterexampleIds[]
  supportCount
  counterexampleCount
  confidence                  # a declared function, not a vibe
  inert: bool                 # true until the PoC's promotion rule fires
  extractorVersion
```

**Confidence function (proposal, to be falsified):**

```text
confidence = supportCount / (supportCount + counterexampleCount)
```

when `supportCount + counterexampleCount ≥ 4`, else `unknown` (not 0). Unknown means "do not apply". A hypothesis with confidence 1.0 and four examples is still a hypothesis.

## Scopes

| Scope | Example | Risk if used too early |
| --- | --- | --- |
| GLOBAL | "Everyone wants 200 ms margin" | Auto-Editor's default. The PoC should show a case where this is wrong |
| USER | This operator's margin | Needs more than one project. Out of the first PoC week |
| PROJECT TYPE | `interview` vs `music` | The first scope the PoC tries to justify |
| PROJECT | This file only | Valid and narrow. Does not prove transfer |
| SCENE TYPE | "wide shot" | No scene detector in v0.1. Scope exists so it is not stuffed into GLOBAL later |

A hypothesis may be stated at `project_type=interview` only if the supporting events carry that tag. Events without a tag do not count. Missing tag is UNKNOWN, not `interview`.

## What the vault refuses

- A model weight.  
- A sentence generated by an LLM about the user.  
- A Good/Bad flag.  
- Automatic change of `ActivityPolicy` without `inert: false` and a human-visible policy id change (`ae-default-v0` → `interview-margin-v1`).  
- Deleting counterexamples when the hypothesis updates.  
- Cross-project facts that include media bytes or paths. Events store ids and millisecond ranges.

## Read path

A later cutter, not built now, may **read** inert hypotheses and must ignore them while `inert` is true. When a hypothesis is promoted to active, the decision's `policyId` changes and `evidenceIds` include the hypothesis id. The peaks remain facts. The preference remains a hypothesis even while it is in use, so a new counterexample can turn it inert again.

**Proposal:** one counterexample does not delete a hypothesis. It increments `counterexampleCount` and recomputes confidence. The promotion rule is re-checked. If it fails, set `inert` true again.

## Relation to Director memory

P1 status says memory is not started. This spec is not a start. It is the boundary: if memory is ever started, correction events and hypotheses are the memory, not a chat log.

## Privacy

A correction event is behavioral data. v0.1 PoC uses local fixtures, not customer projects. A product vault would need a retention rule. **UNKNOWN** and out of scope. Do not design a cloud sync here.
